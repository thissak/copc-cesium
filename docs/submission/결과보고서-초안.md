## 프로젝트 상세 내용

### 개발배경 및 목적

지형·시설물을 측량한 LiDAR 포인트클라우드를 웹 지도에서 보려면, 현재는 원본을 **3D Tiles 형식으로 미리 변환**해야 한다. 이 사전 변환은 세 가지 비용을 만든다.

1. **시간** — 기가바이트급 데이터는 변환에만 수십 분~수 시간이 걸린다.
2. **중복 저장** — 원본과 변환본을 모두 보관해야 해 저장 용량이 두 배가 된다.
3. **재실행** — 원본이 갱신될 때마다 변환 파이프라인을 다시 돌려야 한다.

그런데 **COPC(Cloud Optimized Point Cloud)는 이미 옥트리 구조를 내장한 클라우드 최적화 포맷**이다. HTTP Range 요청으로 필요한 노드만 부분 조회할 수 있으므로, 원리적으로 사전 변환 단계는 불필요하다.

문제는 이 구조를 CesiumJS에 연결하는 **재사용 가능한 오픈소스 통합 계층이 드물다**는 점이었다. 빌딩블록(copc.js, laz-perf, CesiumJS)은 모두 공개돼 있고, 상용 솔루션(Hobu Eptium)은 존재하지만 소스가 공개되지 않는다. 오픈소스 뷰어는 deck.gl 등 CesiumJS가 아닌 렌더러 기반이 대부분이어서, **"오픈소스 ∩ CesiumJS"** 교집합이 비어 있었다.

**목표**: COPC 파일 URL 하나로 CesiumJS에서 LOD 스트리밍이 동작하는 플러그인을, 사전 변환 없이, 표준 Cesium 타입을 반환하는 형태로 제공한다.

### 시스템 구성 및 아키텍처

핵심 설계는 **"LOD를 새로 만들지 않고 CesiumJS에 위임한다"** 이다.

```
COPC 옥트리 (원본 .copc.laz, HTTP Range)
        │
        ▼  노드 1개 = 타일 1개로 매핑
동적 3D Tiles 트리 (tileset.json 을 메모리에서 생성)
        │
        ▼  어떤 노드를 언제 가져올지 = Cesium 이 판단 (Screen Space Error)
Cesium 이 타일 content 를 XHR 로 요청
        │
        ▼  네트워크 계층에서 가로챔
Service Worker (/__copc-real/*)
        │
        ▼  그 노드만 온디맨드 디코드
Web Worker (laz-perf WASM) → pnts 바이너리 응답
        │
        ▼
CesiumJS 렌더 (LOD · 컬링 · GPU 메모리 관리 전부 Cesium 기본 동작)
```

**설계 판단의 근거**

- **왜 Service Worker인가** — Cesium은 타일 content를 `fetch`가 아닌 **XHR**로 가져온다는 것을 진단 스파이크로 확정했다. `window.fetch` 패치로는 가로챌 수 없어, fetch·XHR을 모두 잡는 **네트워크 계층(Service Worker)** 이 유일한 경로였다.
- **왜 표준 `Cesium3DTileset`을 반환하는가** — wrapper 클래스를 만들면 Cesium 생태계의 스타일·피킹·이벤트를 다시 구현해야 한다. 표준 타입을 그대로 돌려주면 `Cesium3DTileStyle`, 피킹, `tileLoad` 이벤트가 **추가 코드 없이** 동작한다.
- **왜 디코드를 Web Worker로 옮겼는가** — laz-perf WASM 디코드가 메인 스레드를 막으면 렌더가 끊긴다. 4축 프로파일러(요청·디코드·좌표변환·렌더)로 병목을 측정해 디코드 축을 분리했다.

상세 근거는 저장소의 `docs/adr/` (아키텍처 결정 기록 7건)에 남겼다.

### 주요 기능 및 특징

**1. 한 줄 통합 — 사전 변환 0단계**
```ts
import { CopcTileset } from '@goldenlabs/copc-cesium';

const tileset = await CopcTileset.fromUrl('https://…/cloud.copc.laz');
viewer.scene.primitives.add(tileset);
```
반환값이 **표준 `Cesium3DTileset`** 이므로 기존 CesiumJS 코드에 그대로 얹힌다. TypeScript strict 환경에서 반환값을 `Cesium3DTileset` 변수에 직접 할당해도 타입 에러가 없음을 배포본으로 검증했다.

**2. Cesium 스타일 언어 그대로 적용**
```ts
tileset.style = new Cesium3DTileStyle({
  color: { conditions: [['${Classification} === 6', 'color("orange")'], …] },
});
```
LAS 분류 코드·강도·리턴 수를 pnts batch table로 노출해, Cesium의 선언적 스타일이 동작한다.

**3. 원본 점 조회 (`snapPoint`)**
화면에 그려진 픽셀이 아니라, **옥트리에서 가장 깊은 노드를 그 시점에 받아 디코드해 실제 최근접 원본 점**을 반환한다. 사전 변환된 타일만 보유한 방식은 원본 점에 접근할 수 없어 구조적으로 제공하기 어려운 기능이다.

**4. 대용량 스트리밍**
하이어라키 서브페이지를 온디맨드로 로드해 기가바이트급 옥트리를 임의 깊이까지 스트리밍한다. 8.9GB 데이터셋으로 90초 스트레스 테스트 시 노드 메타가 2,173 → 14,352로 증가한 뒤 **평탄화(plateau)** 되어 누수가 아님을 확인했다.

**5. 5가지 색상 모드**
RGB · 고도 · 분류 · 강도 · 리턴 수. RGB 차원이 없는 데이터는 고도 색으로 자동 폴백하며, 색 범위는 이상치에 강건하도록 **백분위 클리핑**을 적용한다.

### 향후 확장성 및 기대효과

**적용 가능 분야**
- **국토·도시** — 항공 LiDAR 기반 수치표고모형, 도시 3D 모델링, 건축물 변화 탐지
- **재난·안전** — 산사태·침수 지형 분석, 재난 전후 비교
- **인프라 관리** — 도로·교량·송전선로 MLS(이동식 측량) 데이터 점검
- **문화재** — 정밀 스캔 데이터의 웹 공개

**확장성**
사전 변환 파이프라인이 필요 없으므로, 측량 데이터를 **오브젝트 스토리지에 올리는 즉시** 웹에서 볼 수 있다. 데이터 갱신 주기가 짧은 모니터링 용도에서 특히 효과가 크다.

**기대효과**
- 변환 서버·스토리지 이중화 비용 제거
- Apache-2.0 라이선스로 상용 제품에도 제약 없이 통합 가능
- npm 배포로 `npm install` 한 줄이면 도입 완료

| geometricError 공식 | 이슈 #01에서 under-refine을 **측정으로 확인해 교체** | 상대는 `spacing/2^d` — 우리가 부적합으로 판정했던 식 |
| 경계 볼륨 | region 기반 + CRS 축별 단위 계약(ADR-007) | 상대는 sphere 전용 |
| 좌표 재투영 | 격자 bilinear 근사 **54배** | 상대는 점별 proj4 호출 |
| range 요청 병합 | **61 → 6회** | 상대 미구현 |
| 위치 정밀도 | POSITION_QUANTIZED (uint16×3) | 상대 Float32 |
| 점 예산 | 메모리 한도 기반 유계화 (16 → 89 fps) | 상대 미구현 |
| 재시도·타임아웃 | `p-retry` 기반 복원력 | 상대 미구현 |
| 원본 점 조회 | `snapPoint` 제공 | 상대 미제공 |
| 지오레퍼런싱 검증 | 좌표 **소수점 4자리 일치** | 상대 e2e는 `hypot(center) > 6.2e6`("지구 표면 어딘가") |
| 라이선스 | **Apache-2.0** (상용 통합 제약 없음) | 상대 AGPL-3.0 (카피레프트) |

**(3) 배포 상태**
설계로 끝내지 않고 **npm 배포**(`@goldenlabs/copc-cesium`)와 **라이브 데모**(https://copc-cesium.vercel.app)까지
완료해, 심사자가 설치·실행을 직접 확인할 수 있다.

### 한계점 및 향후 개선 로드맵

**현재 한계**
- **Service Worker 필수** — 브라우저의 Service Worker 스코프가 파일 위치로 결정되어, 소비자 origin에 워커 파일을 복사하는 단계가 필요하다(`msw` 등과 동일한 관행). 가로채기가 불가능하면 조용히 실패하지 않고 명확한 에러를 던진다.
- **`CustomShader` 미지원** — Cesium이 legacy pnts batch table을 CustomShader용 structural metadata로 승격하지 않아 셰이더 컴파일이 실패한다. 측정으로 확인 후 채택하지 않았으며, 디코드 시점에 색을 굽는 방식이 더 견고하다고 판단했다.
- **색 범위 백분위 상수** — 이상치 클리핑 백분위(1–99%)가 현재 고정값이다.

**로드맵**
- 3D Tiles 1.1 / glTF 기반 content 포맷 지원 검토
- 시간축 데이터(4D) 스트리밍
- 색 범위·점 예산 등 노브의 옵션 노출

### 소감 및 후기

가장 크게 배운 것은 **"추측을 측정으로 바꾸는 습관"** 이었다.

초기에 성능 병목을 디코드 속도로 짐작했으나, 4축 프로파일러로 재보니 실제 지배 요인은 **S3 range 요청의 왕복 횟수**였다. 요청을 병합하자 61회가 6회로 줄었다. 좌표 재투영도 마찬가지로 전체 시간의 50%를 차지하던 것이 격자 근사 도입 후 2%로 내려갔다.

반대로 측정 때문에 **포기한 기능**도 있다. 경쟁 라이브러리가 대표 예제로 내세우는 `CustomShader` 지원을 검토했으나, 실제로 돌려보니 셰이더 컴파일이 실패하며 렌더가 통째로 멈췄다. 따라갔다면 결함을 들여왔을 작업이었다.

제출 직전에는 시연영상을 다른 관점에서 교차검토받았고, 그 과정에서 **데모 화면의 노드 카운터가 갱신되지 않는 결함**과 **클릭 후 5초간 반응이 없는 UX 결함**을 발견해 근본 원인까지 수정했다. 영상을 만들려다 제품이 좋아진 셈이다.
